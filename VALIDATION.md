# Звіт про перевірки — 0.1.0

**Гру KSP не запускали. Жоден тест фізичного проходження, відстібання,
повторного сідання, EVA або роботи люка у грі не позначено успішним.**
Це зібраний інсталяційний кандидат, який потребує приймання у KSP 1.12.5.

## Матеріали

- Mk-33 1.3.3.0, commit `fff40f9f602b72f5bad2f7ec888985886d163f98`.
- FreeIVA 0.2.20.2: код, API і офіційна release DLL для компіляції.
- Офіційна wiki FreeIVA, snapshot `ffff9848568fe819a2384322e7cebdedc0d1c623`.
- KSP 1.12.5: публічні build-only reference assemblies з KSPLibs.
  Вони не містять реалізації гри та не дозволяють запускати PhysX/KSP.
- SHA256 досліджених моделей — `source-manifest.json`; перелік сіток і
  кількості вершин/трикутників — `source-mesh-inventory.json`.

У досліджених чотирьох IVA відсутні початкові фізичні колайдери на перелічених
сітках. Просте додавання ModuleFreeIva не створює придатної оболонки.

## Виконані статичні перевірки

| Перевірка | Результат і межі доказу |
|---|---|
| DLL | Зібрана без попереджень з `warnaserror`, проти фактичних API KSP 1.12.5 і FreeIVA 0.2.20.2. Це перевірка сигнатур, не запуск Unity. |
| CFG | Збалансовані вузли, 4 INTERNAL, helper перед IMFIVA, точні назви джерел; локальні MODEL посилання існують. ModuleManager у грі не виконувався. |
| Початкові крісла | Патч не видаляє InternalSeat/моделі крісел; 12 + 16 + 2 + 1 місць збережені в оригінальних конфігураціях. Вихід із сидячого положення ще треба перевірити. |
| Характеристики деталей | PART-патчі додають/налаштовують лише ModuleFreeIva; не редагують паливо, масу, вузли, міцність, аеродинаміку або зовнішні колайдери. |
| Оболонка | Helper будує layer-16, non-trigger, nonconvex MeshCollider з установлених MeshFilter після Cut; подальші візуальні вирізи не налаштовані. |
| Рухомі двері | crewDoor виключені зі статичної оболонки. Native DoorCollider належить рухомим дверям; окремі клік-зони на layer 20 залишаються доступними після відкривання. |
| Експорт .mu | Реальні колайдерні вершини/грані у двох нових .mu збігаються з числовими моделями, за якими проводились перевірки. Шар 16, convex=false, trigger=false. |
| Замкненість стиків | У коридорі 3 заплановані відкриті контури, у короткому переході 2; немає вироджених граней або nonmanifold edges. Шахта й коридор об'єднані до експорту, без внутрішньої заглушки на перетині. |
| Стенд | 8 деталей, зв'язне дерево, 3 взаємні пари stack nodes зі збігом позицій < 0.000001 м. Завантаження craft і стійки у грі ще не перевірені. |
| Ліцензійний склад | У ZIP немає оригінальних моделей/текстур Mk-33 чи FreeIVA, чужих game DLL, reference assemblies або зрізаних копій їхніх трикутників. |

Докладні результати: `package-checks.json`, `exported-model-checks.json`,
`topology-checks.json`, `corridor-clearance-checks.json`,
`original-aperture-checks.json`, `remaining-aperture-checks.json`.

## Геометричні перевірки проходів

Використано параметри штатного FreeIVA: радіус капсули 0.20 м,
висота 0.60 м; для нового коридору також перевірено радіус 0.225 м.
Прорізи в оригінальних сітках змодельовано незалежним від Unity алгоритмом
віднімання опуклого багатогранника з трикутників. Це перевірка заданої
геометрії, а не виконання FreeIVA MeshCutter2 або Unity MeshCollider cooking.

| Вибраний маршрут | Статичний результат |
|---|---|
| Задня заглушка Cockpit | Після вирізу обох шарів мінімальний запас на дискретних позах близько 0.218 м. До вирізу відстань від осі до crewTube лише 0.020 м, до Dashboard 0.051 м — невирізані копії справді блокували б капсулу. |
| Тунель Krew, спереду назад | Мінімальний запас на дискретних позах близько 0.142 м після вирізу crewTube та cabinMesh з обох кінців. |
| Наявні верхні двері Cockpit, відкриті | Запас близько 0.068 м на заданій траєкторії. Додатковий проріз підлоги/стіни не потрібен. |
| Доданий коридор, шахта та верхня горловина | Перевірені обидва напрямки, крок до 5 мм; найменша консервативна оцінка зазору 0.055 м у верхній горловині. |
| Короткий перехід Krew–Airlock | Обидва напрямки; консервативний запас понад 0.227 м для перевіреної осі. |
| Airlock, передній/задній отвори | Консервативна оцінка зазору 0.170 м на заданій осі після вирізів. |
| Airlock, верхній отвір | Консервативна оцінка 0.312 м на вертикальній осі. |
| Krew, верхній отвір | Консервативна оцінка 0.117 м для вибраної вертикальної осі; це не перевірка стикування з іншою деталлю. |
| Control Cab, верхній отвір | Консервативна оцінка 0.092 м на вибраній вертикальній осі. |

Усі ці цифри стосуються **конкретних перевірених траєкторій**. Вони не доводять,
що персонаж може дістатися кожної траєкторії з кожного крісла, що коректно
працює контакт ніг із підлогою, драбина, гравітація, фізичне приготування сіток
або фактичне виконання вирізу у завантажувачі KSP. У таблиці оригінальних
сіток перші три числа є оцінками на дискретних позах; міжпозовий рух
потребує додаткового запасу та ігрового тесту.

## Що залишається перевірити у KSP

Усі пункти нижче мають статус **НЕ ВИКОНАНО**:

1. Завантаження DLL, порядок InternalModule, фактичні MeshCutter2 і PhysX;
   відсутність винятків/помилок у `KSP.log`.
2. Вихід із пілотських, пасажирських та шлюзових крісел без застрягання;
   доступ з кожної палуби до її виходу.
3. Підлога, стіни, обладнання й вікна утримують персонажа; немає провалювання.
4. Кожний люк закритим блокує рух, відкритим пропускає, після повернення
   знову закривається. Реальний перехід в обидва боки є обов'язковим.
5. Правильне визначення поточного відсіку, повернення та повторне сідання.
6. Задній і верхній EVA-люки Airlock, посадка назад з EVA; окремо Control Cab.
7. Висування docking tube Krew, стикування з конкретним сумісним житловим
   модулем і безперервний фізичний перехід через цей стик.
8. Повторення після quicksave/quickload, повторного входу в IVA, відстикування;
   блокування нез'єднаних люків, особливо дальнього виходу коридору.

Повний порядок дій — `instructions.md`. Візуальне відкривання без проходження
є невдалим тестом. Пакет не оголошується повністю прийнятим до виконання цих
перевірок у грі.
