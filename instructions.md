# Статичний стенд Mk-33 FreeIVA

**Цей `.craft` створено програмно. Його не відкривали й не запускали у KSP.**
Перевірено лише граф кріплень і збіг координат трьох пар вузлів. Це не є
підтвердженням роботи завантажувача KSP, стійок, FreeIVA або фізичного проходження.

## Встановлення стенда

1. Установіть Mk-33, FreeIVA та цей патч за основним README.
2. Скопіюйте `Mk33_FreeIVA_Test.craft` з цієї папки до
   `<KSP>/saves/<назва_збереження>/Ships/SPH/`.
3. Відкрийте апарат **Mk33 FreeIVA Static Test** в ангарі SPH у Sandbox.
4. Призначте щонайменше двох кербалів у **Mk-33 Cockpit**. Для першого тесту
   залиште Krew Module та Airlock без екіпажу, щоб мати вільні місця для пересадки.
5. Перевірте чотири штатні launch clamps: вони мають утримувати корпус над
   землею. Їхню орієнтацію та висоту веж не перевірено у грі. За потреби
   перевстановіть стійки засобами редактора, зберігши положення чотирьох
   деталей Mk-33. Не зміщуйте їх інструментом Offset.
6. Запустіть стенд на смугу. **Не активуйте ступінь зі стійками.** Двигунів,
   крил і льотного шасі в ньому немає; це стенд для перевірки інтер'єрів.

У стенді порожні паливні баки. Їхні `maxAmount` відповідають оригінальним
конфігураціям; це налаштування конкретного апарата, а не зміна характеристик мода.

## Схема кріплень

| Деталь / вузол | З'єднана деталь / вузол |
|---|---|
| `Mk33Cockpit.bottom` | `Mk33MidTank.top` |
| `Mk33MidTank.MissionModuleNode1` | `wbiMk33KrewModule.mount` |
| `wbiMk33KrewModule.bottom` | `wbiMk33Airlock.top` |

FreeIVA використовує на середньому баку логічний маршрут
`top ↔ MissionModuleNode1`. Фізичний коридор додається патчем до IVA кабіни.
Установлений на нижньому вузлі Krew Module шлюз займає порожнє місце другого
mission module: **не встановлюйте туди кришку вантажного відсіку чи іншу деталь.**

Для цієї схеми центри чотирьох деталей в локальних координатах кабіни:

| Деталь | X, Y, Z, м |
|---|---|
| Cockpit | `0, 0, 0` |
| MidTank | `0, -7.70157, 0` |
| Krew Module | `0, -3.95157, -0.00207` |
| Airlock | `0, -6.45061, -0.00207` |

Орієнтації однакові. У `.craft` увесь блок повернуто горизонтально для SPH.
Не застосовуйте TweakScale, поворот або зміщення окремих деталей до завершення
базового тесту. Коридор розраховано на зазначене компонування.

## Обов'язкові перевірки у грі

За замовчуванням FreeIVA використовує `Y` для відстібання/пристібання,
`WASD` для руху й мишу для взаємодії з люками. Якщо керування змінено,
використовуйте власні налаштування FreeIVA.

Перевірте кожен пункт і запишіть результат. Наразі **всі пункти нижче мають
статус «НЕ ПЕРЕВІРЕНО У KSP»**.

| Тест | Критерій успіху |
|---|---|
| Відстібання в кабіні | Кербал виходить із крісла без застрягання та викидання за оболонку. |
| Переміщення між рівнями кабіни | Можна фізично дістатися нижнього проходу від пілотських місць і повернутися. |
| Підлога, стіни, обладнання | Утримують кербала; немає провалювання або проходження крізь меблі. |
| Закритий внутрішній люк | Перекриває рух перед відкриванням. |
| Кабіна → Krew | Відкрити люки й пройти весь коридор власним керуванням без Transfer Crew. |
| Krew → кабіна | Повернутися через той самий прохід і закрити люки. |
| Krew → Airlock | Пройти відкриті люки, включно зі стиком короткого перехідного тунелю. |
| Airlock → Krew | Повернутися, закрити люки; закриті двері знову блокують рух. |
| Крісла | Сісти на вільне місце в кожному населеному модулі й знову відстібнутися. |
| Зовнішній люк Airlock | Виконати EVA через зовнішній люк, потім повернути кербала через штатний вхід. |
| Збереження/завантаження | Після quicksave/quickload повторити проходження в обидва боки. |
| Журнал | Немає помилок завантаження DLL, відсутніх transform, mesh cut або з'єднань FreeIVA. |

**Відкрита картинка наступного відсіку не означає успіх.** Якщо персонаж
упирається в невидиму площину, зафіксуйте помилку саме для цього люка.
Не використовуйте телепортацію, вимкнення колізій, Transfer Crew чи noclip як
заміну проходженню. Звичайний вихід EVA самою грою є окремою штатною дією.

Для звіту про проблему збережіть `KSP.log`, точні версії Mk-33/FreeIVA/патча,
назву люка, напрямок руху й положення кербала перед перешкодою. Для перевірки
повторного сідання також укажіть номер крісла та чи було воно зайняте.

## Що підтверджено без гри

- Вісім різних ID деталей, дерево без циклів, кожна нерутова деталь має батька.
- Для трьох пар stack nodes присутні взаємні `attN`, а `link` задає відповідне дерево.
- Координати кінців кожної пари збігаються з похибкою менше `0.000001 м`;
  напрямки вузлів протилежні.
- Значення вузла `MMNode001` узгоджуються з оригінальним `.mu` середнього бака
  та прикладом складання Mk-33.
- За перевіркою меж зовнішніх колайдерів шлюз поміщається в порожнє друге
  місце: приблизно `0.151 м` до бічних стін і `0.255 м` до задньої стінки бака.
  Центральний напрямок виходу верхнього EVA-люка не перетинає AABB колайдерів
  бака на перших `0.5 м`. Це приблизна геометрична перевірка, не тест EVA у KSP.

Числовий результат міститься в `topology-checks.json`. Перебудувати стенд і
повторити його статичні перевірки можна командою
`python3 ../Source/generate_test_craft.py` із цієї папки.
